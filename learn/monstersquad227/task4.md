## ① 定位：我们做的 Swap 在 DeFi 里是哪一环

Swap 是 DeFi 最底层的能力之一：**点对点兑换资产**。课程里做的 DApp，本质上是一个小型 DEX——用户把 Token A 换成 Token B，中间不需要撮合对手盘，而是靠流动性池（Liquidity Pool）自动定价。

这套定价靠的是 **AMM（Automated Market Maker，自动做市商）**。最经典的模型是 Uniswap V2 那套恒定乘积：

\[
x \cdot y = k
\]

k是恒定的，x表示在这个交易所中这个池子里面有多少的代币，y表示这个交易所里面有多少真实的USDC。举一个例子：Uniswap交易所；x 里面有 100mon代币，y 里面有 10000 USDC，k 值为1000000；此时一个 mon代币价值 100USDC；现在有一个人买了 80个mon代币，x' = 100 - 80 = 20, k = 1000000, y' = 1000000 / 20 = 50000, 这个人需要花费 50000 - 10000 = 40000 USDC，那么此时 x = 20, y = 50000, k = 1000000, 一个 mon代币价值 2500USDC。意味着 mon代币升值了；


所以 Swap 在 DeFi 地图上的位置是：**基础交易层**。有了它，才有价格发现、才有 LP、才有后面用「池子价格 / 预言机价格」做抵押估值和清算的一整套玩法。没有可靠的兑换，借贷和衍生品几乎无从谈起。

## ② 梳理：DeFi 的发展进程

可以粗略看成几条台阶，一层解决上一层「还不够」的问题。

### 阶段一：DEX / Swap —— 先让资产能自由换

- **代表：Uniswap**
- **解决什么**：中心化交易所要 KYC、要托管资产，链上又没有传统订单簿撮合。AMM + 流动性池让任何人都能做市、任何人都能兑换，交易变成一套公开合约逻辑。

后来还有 Curve（稳定币低滑点）、Trader Joe / Pangolin（Avalanche 生态 DEX）等，但主线不变：**去中心化现货交易**。

### 阶段二：借贷协议 —— 让闲置资产生息、让急需资金的人借出

- **代表：AAVE、Compound**
- **解决什么**：只有 Swap，资产要么闲着要么卖掉。借贷协议把存款人的资产汇入资金池，借款人抵押后借出另一种资产；利率由利用率算法动态调整。存款人赚利息，借款人获得流动性，而不必立刻卖掉持仓。

这一步把 DeFi 从「兑换」推进到「信用创造（虽然还是抵押信用）」——链上开始有真正的资金市场。

### 阶段三：衍生品 / 期货 / 永续合约 —— 对冲、杠杆、做空

- **代表：dYdX、GMX、Synthetix**
- **解决什么**：现货只能「买了等涨」。交易者需要杠杆、做空、对冲价格风险。永续合约（Perpetual）用保证金、标记价格、资金费率等机制，让用户在不交割现货的情况下押注价格方向。

### 阶段四及以后：聚合、稳定币、RWA、跨链……

- **聚合器**（如 1inch）：路由最优 Swap 路径；
- **稳定币 / CDP**（如 MakerDAO）：超额抵押生成稳定币；
- **收益聚合**（如 Yearn）：自动在借贷/挖矿间切换；
- **RWA、Restaking、Intent 交易** 等：把更多真实世界资产和更复杂策略搬上链。

整条主线可以记成一句话：

> **先能换（DEX）→ 再能借（Lending）→ 再能赌方向和对冲（Derivatives）→ 再把这些能力组合、跨链、对接现实金融。**

## ③ 回答：借贷和期货分别怎么实现

### 借贷：超额抵押 + 利息模型 + 清算

链上借贷和银行不一样——合约不知道你的信用分，所以默认走 **超额抵押**：

1. **存款（Supply）**  
   用户把资产存进资金池，合约铸造对应的 aToken / 凭证，代表你对池子的份额，余额会随利息增长。

2. **借款（Borrow）**  
   用户用已存资产作抵押，借出另一种资产。关键参数是 **LTV（Loan-to-Value）** 和 **清算阈值（Liquidation Threshold）**。例如抵押价值 100，最多只能借 70～80，留出安全垫。

3. **健康因子（Health Factor）**  
   大致是「抵押品价值 × 清算阈值 / 债务价值」。健康因子跌到 1 以下，仓位可被清算。

4. **清算（Liquidation）**  
   清算人代还部分债务，按折扣价拿走抵押品，赚清算奖励；协议借此避免坏账。价格通常来自 **预言机**（Chainlink 等），而不是单靠某一个 AMM 池瞬间价格，以免被操纵。

5. **利率**  
   常见是利用率模型：借得越多、池子越空，利率越高，激励存款、抑制过度借贷。

合约逻辑上，核心状态就是：各资产的 `totalSupply` / `totalBorrow`、用户抵押与债务、预言机价格、以及触发清算的条件判断。没有「信用」二字，全靠抵押品和清算机器人。

### 期货 / 永续：保证金 + 预言机标记价 + 资金费率

链上更常见的是 **永续合约（Perp）**，没有交割日，靠资金费率锚定现货：

1. **开仓与保证金**  
   用户存入保证金（如 USDC），按杠杆开多/开空。仓位价值 = 名义本金，但实际占用的是保证金。保证金率不足会被强制平仓。

2. **标记价格（Mark Price）**  
   盈亏和清算一般不直接用某个薄池子的现货价，而是用预言机或指数价，减少插针爆仓。

3. **对手盘从哪来？**  
   - 订单簿模式（如早期 dYdX）：链下撮合 / 链上结算；  
   - 流动性池 / GLP 模式（如 GMX）：交易者对协议池子下注，盈亏由池子 LP 承担；  
   - 合成资产模式（如 Synthetix）：债务池对冲。

4. **资金费率（Funding Rate）**  
   多头拥挤时，多头付费给空头（反之亦然），把合约价格往现货拉近。这是永续能「永远不平仓交割」的关键设计。

合约侧要维护：仓位方向与规模、保证金余额、资金费率累计、强平逻辑，以及可信的价格喂价。和 Swap 比，复杂度从「算一笔兑换」变成了「持续盯风险」。

## ④ 展望：如果扩展我们的课程 Swap DApp

我会优先加 **借贷**，而不是一上来做永续——借贷和我们已有的「代币 + 池子 + 价格」更顺，也更容易在 Fuji 测试网上自洽。

### 设计思路（最小可用版）

1. **复用现有资产**  
   课程 Swap 里已有 Token A / Token B 和流动性池。新增一个 `SimpleLending` 合约：接受 A、B 存款；允许用 A 抵押借 B（或反过来）。

2. **价格来源**  
   第三章已经练过从 DEX Pair / Quoter 读价。借贷估值可以：  
   - 开发阶段：直接读 Pair 储备量算出相对价格；  
   - 更稳妥：接 Chainlink（或测试网 mock oracle），避免单池被砸盘操纵后错误清算。

3. **核心参数**  
   - 抵押率 / LTV：例如 70%；  
   - 清算线：例如 80%；  
   - 清算奖金：例如 5%；  
   - 简单线性利率：`borrowRate = base + utilization * slope`。

4. **关键函数草图**  
   - `deposit(asset, amount)`：转入资产，记份额；  
   - `borrow(asset, amount)`：检查健康因子后放款；  
   - `repay` / `withdraw`：还债、取回多余抵押；  
   - `liquidate(user)`：任何人可调用，健康因子 < 1 时代还并拿走抵押。

5. **前端路径**  
   在现有 Swap 页面旁加「Earn / Borrow」页：展示存款余额、可借额度、健康因子；清算可先做管理员演示按钮，再开放给公共清算人。

6. **若以后再加期货**  
   可在同一套预言机上做极简「二元仓位」：存 USDC 保证金 → 开多/空 → 用标记价结算盈亏 → 保证金率不足强平。对手盘先用协议自有金库（类 GMX），避免一上来就做订单簿。

一句话总结扩展路径：

> **Swap 负责兑换与价格种子 → Oracle 把价格变可信 → Lending 用超额抵押和清算把「闲置流动性」变成可借贷市场；期货则是在借贷风控之上再加杠杆与方向仓位。**

对我们的课程 DApp 来说，先把「存款—借款—清算」跑通，就已经从「能换」跨到「能借」，这才是从即时交易走向更完整 DeFi 的第一步。
