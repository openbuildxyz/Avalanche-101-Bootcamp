# Task 4：从“换币成功”到一套能运转的金融系统

> 学员：jeffierw

## ① 我们做的 Swap 在 DeFi 里是哪一环

我最早做的项目以 JavaScript、TypeScript 和前端为主。站在前端看 Swap，它很像一个简单流程：连接钱包、输入数量、确认交易。真正写过合约后才发现，按钮背后最重要的不是页面，而是谁提供价格和流动性。

AMM 给出的答案是流动性池。恒定乘积模型让两种资产的储备满足 `x * y = k`。一种资产被买走后储备减少，价格自然上升；交易相对池子越大，滑点越明显。流动性提供者则用承担风险换取手续费。

我的 Task 3 在 Fuji 上创建了 `ABTv2/WAVAX` 池，注入 `10,000 ABTv2` 和 `0.02 WAVAX`。用户支付 `0.001 AVAX` 时，LFJ 实际报价约 `474.83 ABTv2`，合约再按报价转账。这让我直观看到：价格不是配置里的数字，而是池子状态和交易共同产生的结果。Swap 因而是 DeFi 的交易与价格发现层，也是上层协议的地基。

## ② DeFi 是怎样一层层长出来的

我更愿意按“解决了什么问题”理解 DeFi，而不是背一条年份时间线。

第一层是以 **Uniswap** 为代表的 DEX，解决资产如何在没有中心化撮合的情况下交换，也让任何人都能提供流动性。

有了价格和流动性，下一步就是提高资金利用率。以 **Aave** 为代表的借贷协议让持币者无需卖出资产也能借款，并让闲置资金获得利息。

再往上是以 **dYdX、GMX** 为代表的永续合约和衍生品。用户无需买入标的资产，也可以做多、做空或对冲；交易的从 Token 变成了价格风险。

聚合器和收益策略又把 Swap、借贷、质押组合起来。过去做 Sui、Walrus 和跨链项目时，我常把钱包、存储和支付拼成一条产品流程；DeFi 也很像这样，只是底层模块出错时，影响的是真实资产。

## ③ 借贷和期货在链上怎么实现

链上借贷通常要超额抵押，因为合约无法审核收入，也无法在线下追债。用户存入抵押品后，协议根据预言机价格计算价值，再通过 LTV 限制借款上限。健康因子可以简单理解为：

`健康因子 = 抵押品价值 × 清算阈值 / 债务价值`

低于安全线时，清算人可以替借款人还债，并折价获得抵押物。奖励促使外部参与者及时清除风险，避免坏账。核心逻辑就是存款、借款、计息、还款、赎回和清算，而预言机决定计算是否可信。

永续合约维护的是保证金和仓位账本。合约记录方向、仓位和开仓价，根据标记价格计算盈亏；保证金不足时强制平仓。因为没有到期日，还需要资金费率让多空双方定期支付，使合约价格贴近现货。高杠杆也会把价格延迟和流动性不足迅速放大。

## ④ 如果继续扩展我的 DApp

我会先做借贷，而不是一上来做期货。借贷已经能把价格、资产、利息和清算串成完整闭环，也更容易把风险讲清楚。

第一版让用户抵押 WAVAX，借出测试稳定币。`LendingPool` 记录抵押和债务，`OracleAdapter` 读取价格，清算函数允许第三方还债并获得抵押品。教学版本先采用固定利率和固定抵押参数。

Task 3 的池子只有 `0.02 WAVAX`，即时价格很容易被大额交易或闪电贷改变，不能直接用于清算。我会以可靠外部预言机为主、DEX TWAP 为交叉检查，并拒绝过期或偏差过大的报价。前端也必须显示健康因子、预计清算价、利息和授权范围。做过不少前端后，我越来越觉得，风险如果只写在合约里而没有让用户看懂，产品仍然没有真正完成。
