# 我的提交

## ① 定位：我们做的 Swap 在 DeFi 里是哪一环

我们课程中实现的 Swap 属于 DeFi 最基础的一层：**去中心化交易（DEX）**。它解决的问题是：用户不需要中心化交易所，也不需要把资产交给平台托管，就可以直接通过智能合约完成一种 Token 到另一种 Token 的交换。

课程中的 Swap 本质上采用了 AMM（Automated Market Maker，自动做市商）模型。与传统交易所依赖买单和卖单不同，AMM 把两种 Token 放进一个流动性池（Liquidity Pool），用户直接和池子交易。

以经典的 Uniswap V2 模型为例，假设池子中有 Token A 和 Token B，储备量分别为 `x` 和 `y`，核心关系可以表示为：

```text
x * y = k
```

用户增加一种 Token 后，合约根据这个恒定乘积关系计算可以得到多少另一种 Token。交易完成后，池子的两个储备量发生变化，但会尽量保持这个不变量。流动性提供者（LP）则向池子提供两种 Token，并通过交易手续费获得收益。Uniswap 官方文档也将 AMM 描述为由流动性池和定价公式完成链上交易的机制。

从合约角度看，一个简单的 DEX 通常可以拆成几个部分：

* **Token 合约**：负责 ERC-20 Token 的余额和转账；
* **Pair/Pool 合约**：保存两种 Token 的流动性和储备量；
* **Router 合约**：负责调用 Pair，完成添加流动性和 Swap 等操作；
* **Oracle**：从链上市场数据中获得价格信息，为其他 DeFi 应用提供参考价格。

AMM不再依赖传统交易所的挂单撮合订单簿，而是依靠**恒定乘积公式**（Uniswap V2：x*y = k）。交易对池内存放两种代币，`x`、`y`分别代表两种代币储备量，`k`为恒定乘积。用户进行Swap时，存入一种代币，池内储备量改变，自动算出另一种代币的输出数量。就像我们Fuji测试网部署的Pair合约，`getReserves()`读取池子两种代币储备，以此计算兑换价格。
AMM解决了链上缺少对手盘、无法高效撮合交易的痛点，为后续所有DeFi应用提供代币兑换、流动性来源，是DeFi生态的入口。


## ② 梳理：DeFi 的发展进程

DeFi 的演进可以粗略分为四个阶段，每个阶段都在解决前一个阶段的“不完整”。

**第一阶段：DEX 与 Swap（2017–2019）** 。早期 DEX 如 0x、Kyber 尝试把订单簿搬到链上，但链上挂单成本高、流动性差。2017 年 Bancor 首先提出自动做市概念，2018 年 Uniswap 用极简的常数乘积公式实现了真正的链上无需许可交易。它解决了“如何在不依赖做市商的情况下让任何人有得交易”的问题。代价是 LP 承担无常损失，但相对于“根本没人交易”，这是可接受的。

**第二阶段：借贷协议（2017–2020）** 。Swap 让资产能换，但持有资产的人只有“卖”或“持有”两个选择。借贷协议给了第三个选项：抵押生息。MakerDAO 是最早的先行者，允许用户超额抵押 ETH 生成稳定币 DAI。Aave 和 Compound 随后把借贷标准化：存款人存入资产赚取利息，借款人超额抵押借出，利率由资金利用率动态调节。它解决了“闲置资产的资本效率”问题——你不必卖掉 ETH 也能获得流动性。

**第三阶段：衍生品与期货（2020–2022）** 。借贷协议做的是现货杠杆，而衍生品满足的是**对价格波动本身下注**的需求。dYdX 把永续合约带上链：没有到期日，用资金费率锚定现货价格，用户以稳定币作为保证金即可开多开空。它解决了“链上对冲和投机”的问题，让 DeFi 从一个“借贷市场”升级为完整的“金融市场”。

为了实现这种机制，协议通常需要：

1. **价格预言机（Oracle）**：获得可靠的资产市场价格；
2. **保证金（Margin）**：用户必须提供一定数量的抵押资金；
3. **仓位管理**：记录用户的多头、空头、杠杆和未实现盈亏；
4. **清算机制**：当保证金不足以覆盖风险时关闭仓位；
5. **资金费率（Funding Rate）**：通过多空双方之间的周期性资金支付，使永续合约价格尽量接近现货价格。

**第四阶段：模块化与聚合（2022至今）** 。DEX 聚合器（如 1inch）解决流动性碎片化，借贷协议开始做隔离市场（Aave V4 的 Hub & Spoke 架构），衍生品协议探索链下订单簿+链上结算的混合模式。这个阶段的关键词是“效率”和“专业化”。

DeFi 并不是一次性出现的，而是从最基本的链上资产交易逐渐发展出借贷、衍生品、资产管理等更复杂的金融应用。


## ③ 回答：借贷和期货分别怎么实现
**借贷协议**  
- **核心机制**：超额抵押。借款人必须抵押价值高于贷款的资产（例如抵押 150 美元 ETH 才能借 100 美元 USDC）。  
- **清算机制**：当抵押品价值跌破安全阈值，系统会自动卖出抵押品，保证贷款人资金安全。  
- **关键合约逻辑**：  
  - Collateral 合约：存入抵押品并记录价值。  
  - Lending 合约：发放贷款，计算利息。  
  - Liquidation 合约：监控抵押率并触发清算。

**期货/衍生品协议**  
- **核心机制**：保证金 + 资金费率。  
  - 用户存入保证金，按杠杆倍数开仓。  
  - 永续合约通过资金费率机制让合约价格锚定现货。  
- **预言机作用**：链上无法直接获取市场价格，需要预言机（如 Chainlink）提供外部价格数据。  
- **关键合约逻辑**：  
  - Margin 合约：管理用户保证金和仓位。  
  - Funding 合约：定期结算资金费率。  
  - Oracle 合约：提供价格输入，触发清算。

## ④ 展望：如果扩展我们的 DApp
按照 DeFi 的发展路线逐步增加功能。

### 第一阶段：Swap + Oracle

首先保留现在的：

```text
Token
 ↓
Pair
 ↓
Router
 ↓
Swap
```

然后增加：

```text
Pair
 ↓
Oracle
 ↓
PriceFeed
```

Oracle 可以使用 DEX 的历史价格计算 TWAP，而不是简单读取当前储备量。这样可以降低单笔交易瞬间改变价格所带来的影响。Uniswap v2 的 Oracle 设计就是通过累计价格和时间窗口计算 TWAP。

### 第二阶段：增加 LendingPool

在 Swap 上增加一个 `LendingPool`：

```text
User
 ↓
Deposit
 ↓
LendingPool

User
 ↓
Collateral
 ↓
Borrow
```

然后根据抵押物价值计算用户是否可以借款。

就从单纯的交易平台变成了一个简单的 DeFi 资金市场。

### 第三阶段：增加 PerpetualMarket

如果继续实现期货/永续功能，可以增加一个 `PerpetualMarket` 合约。用户先存入保证金。合约记录开仓价格和仓位大小。之后根据 Oracle 的价格计算盈亏。当保证金率低于清算阈值时，允许清算者关闭仓位。

### 我的整体设计思路

如果把课程中的 Swap 继续发展，我会按照：

```text
Swap
  ↓
Oracle
  ↓
Lending
  ↓
Liquidation
  ↓
Perpetual
  ↓
Funding Rate
```
每增加一层功能，都会复用上一层已经解决的问题。

Swap 解决**交易和价格发现**；

Oracle 解决**链上价格数据**；

Lending 解决**资金借贷和抵押**；

Liquidation 解决**风险控制**；

Perpetual 则进一步解决**杠杆、多空和衍生品交易**。

从这个角度看，DeFi 并不是几个独立的智能合约，而更像是一套可以相互组合的金融基础设施。完成的 Swap 虽然功能比较简单，但它实际上已经构成了后续借贷、衍生品等复杂 DeFi 应用所需要的一块基础设施。
