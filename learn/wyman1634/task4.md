# Task 4：从 Swap 走向借贷与衍生品

> 学员：wyman1634

## ① 定位：课程 Swap 在 DeFi 中是哪一环

Swap 属于 DeFi 的交易与流动性基础层。传统交易依靠订单簿匹配买卖双方，AMM 则让流动性提供者先把两种资产存入池子，用户直接与合约交易。以常数乘积模型为例，池中两种资产的储备满足 `x * y = k`：买走一种资产后，它在池中的数量减少，价格就会上升；交易量相对池子越大，价格冲击和滑点越明显，手续费则补偿流动性提供者承担的风险。

我的 Task 3 在 Fuji 上创建了 `ABTv2/WAVAX` LFJ V1 交易对，初始储备为 `10,000 ABTv2 + 0.05 WAVAX`。合约通过 Router 读取这个池子的实时报价，再决定用户支付 AVAX 后得到多少 ABTv2。这说明 Swap 不只提供兑换，也为上层应用提供流动性和可观察的市场价格。

## ② 梳理：DeFi 的发展进程

我更愿意把 DeFi 的发展理解为能力逐层组合，而不是互相替代。

第一层是以 **Uniswap** 为代表的 DEX。AMM 让资产无需中心化做市商也能持续交易，解决“链上资产如何兑换和形成价格”的问题。

第二层是以 **Aave** 为代表的借贷协议。存款人的资产进入资金池并获得利息，借款人抵押资产后借出另一种资产，解决“持有资产但不想卖出时如何获得流动性”的问题。

第三层是以 **dYdX** 为代表的衍生品和永续合约。用户通过保证金建立多头或空头仓位，获得杠杆与对冲能力，解决“如何交易价格风险而不是只交换现货”的问题。

之后出现了 **1inch** 等聚合器和各种收益金库。它们组合多个 DEX、借贷池和策略，解决流动性分散、交易路径不佳以及人工管理策略成本高的问题。DeFi 的核心价值也由单一协议扩展为合约之间可组合的金融流程。

## ③ 回答：借贷和期货分别怎么实现

链上借贷通常采用超额抵押，因为合约无法像银行一样追讨无抵押欠款。用户先存入抵押品，Oracle 提供抵押品和债务资产的价格，合约再根据 LTV、清算阈值和累计利息计算健康因子。用户可以存款、借款、还款和赎回；如果价格下跌或债务利息增加，使健康因子低于安全线，任何清算人都可以替借款人偿还部分债务，并折价获得一部分抵押物。清算奖励促使外部参与者及时消除坏账风险。

期货或永续合约维护的则是保证金和仓位账本。用户存入保证金后，合约记录方向、仓位大小和开仓价格，并根据 Oracle 的指数价格或标记价格计算未实现盈亏。亏损使保证金低于维持保证金时，仓位可以被强制平仓。永续合约没有到期日，因此还需要资金费率：多空力量失衡时，由一方向另一方定期付费，让合约价格回到现货价格附近。关键风险包括 Oracle 延迟或操纵、价格剧烈跳变、清算不及时，以及高杠杆造成的坏账。

## ④ 展望：扩展我们的 DApp

我会先增加借贷而不是期货，因为它与现有 Swap 和 Task 3 价格读取最容易形成完整闭环。系统可以拆成 `LendingPool`、`OracleAdapter` 和 `LiquidationEngine`：用户抵押 WAVAX，借出测试稳定币；最大借款价值设为抵押品的 50%，债务达到风险调整后抵押价值时允许清算；清算人偿还稳定币并取得带奖励的 WAVAX，再通过 LFJ Swap 变现。

Task 3 的池子很浅，即时储备价格可以用于学习报价，却不能直接成为生产清算价格，否则攻击者可能用大额交易或闪电贷短暂改变价格。我会使用可靠外部数据源作为主价格，DEX TWAP 作为交叉检查，并拒绝过期价格或偏差过大的报价。合约还应处理 Token decimals、重入、暂停、资产上限和最小流动性；钱包前端要明确展示授权、健康因子、预计清算价、交易处理中和链上失败。这样扩展的不只是一个按钮，而是一条可监控、可验证并有清晰风险边界的借贷流程。
