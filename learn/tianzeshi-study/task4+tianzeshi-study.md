# DeFi 的发展进程：从 Swap 到借贷与期货

## ① 定位：我们做的 Swap 在 DeFi 里是哪一环

课程里实现的即时交易，本质上是一个 AMM（自动做市商，Automated Market Maker），属于 DeFi 里最基础的一层——流动性/交易层（DEX）。整个 DeFi 生态可以粗略理解成一个"金融乐高"：交易层负责让资产能够自由定价、自由兑换，其他所有更复杂的玩法（借贷、杠杆、衍生品）几乎都要依赖这一层提供的价格信号和流动性。

AMM 的基本原理不是撮合买卖双方的挂单（不像传统交易所的订单簿），而是靠一个数学公式和一个资金池来自动定价。以最常见的恒定乘积公式为例：

```
x  y = k
```

池子里存着两种代币（比如 TokenA 和 TokenB），`x` 和 `y` 分别是它们的数量，`k` 是一个常数。用户拿 TokenA 换 TokenB 时，实际上是往池子里"扔"进一些 TokenA，池子会按公式自动算出应该"吐出"多少 TokenB，保证乘积 `k` 不变。这样一来：

- 价格完全由池子里两种资产的比例决定，兑换量越大，滑点越大；
- 不需要对手方挂单，只要池子里有流动性，随时可以成交；
- 流动性提供者（LP）把资产存入池子赚手续费，同时承担无常损失的风险。

这套机制解决了 DeFi 最底层的问题——"资产怎么在没有中心化撮合方的情况下自由定价和流通"，是后面所有玩法的地基。

## ② 梳理：DeFi 的发展进程

DeFi 的演进大致可以按"解决的问题"分成几个阶段：

阶段一：DEX / Swap（2018 前后起步）
代表协议：Uniswap。它用 AMM 模型解决了"链上如何无许可地交易任意代币"的问题，不需要中心化交易所审核上币，任何人都能创建一个交易对。这是 DeFi 的起点，因为有了它，链上资产才第一次有了"价格"和"流动性"。

阶段二：借贷协议（2019-2020）
代表协议：AAVE（早期叫 ETHLend）、Compound。它们解决的问题是"我有闲置资产想赚利息，或者我想加杠杆但不想卖掉手里的币"。用户可以把资产存入协议赚利息，也可以抵押资产借出别的币种，实现了链上的信用扩张（虽然是超额抵押型信用）。这一步让 DeFi 从单纯的"交易"扩展到了"资金的时间价值"。

阶段三：衍生品 / 期货 / 永续合约（2020-2021）
代表协议：dYdX、GMX、Perpetual Protocol。它们解决的问题是"我想用杠杆做多做空，而不需要真的持有资产"。这一步依赖前两个阶段——需要借贷提供杠杆资金，需要 DEX/预言机提供价格。永续合约的出现让 DeFi 第一次能模拟传统金融里的期货交易。

阶段四：收益聚合与结构化产品（2021 前后）
代表协议：Yearn Finance。它把"把资产在各个借贷/流动性协议之间自动搬运找最优收益"这件事自动化，解决的是"用户不想自己研究策略"的问题，标志着 DeFi 开始出现"组合协议"，也就是我们常说的"金融乐高"真正拼起来了。

阶段五：LSD / Restaking / RWA（2022 至今）
代表协议：Lido（流动性质押）、EigenLayer（再质押）。这一阶段解决的是"质押的资产被锁死不能用"的问题，让质押凭证本身也能成为 DeFi 里流通的资产，进一步提高资金效率；同时也开始探索把链下真实资产（国债等）搬上链。

可以看到，整体脉络是：先有价格和流动性（DEX）→ 再有信用和杠杆（借贷）→ 再有对未来价格的博弈工具（衍生品）→ 最后是资金效率的持续优化（聚合、再质押）。

## ③ 回答：借贷和期货分别怎么实现

借贷：核心是超额抵押 + 清算机制

以 AAVE/Compound 为代表的借贷协议，核心逻辑并不复杂：

1. 存款：用户存入资产，获得计息凭证（比如 AAVE 的 aToken），凭证数量或汇率会随时间增长，代表利息累积。
2. 借款：用户存入一种资产作为抵押物，可以借出另一种资产，但只能借出抵押物价值的一部分（比如抵押 100 美元的 ETH，最多借 70-80 美元的 USDC），这个比例叫抵押率或LTV（Loan-to-Value）。之所以要求"超额"抵押，是因为链上没有征信体系，无法追债，只能靠资产本身作担保。
3. 利率模型：借款利率通常由资金池的"利用率"（借出去的资金 / 池子总资金）动态决定，利用率越高利率越高，用市场化的方式激励存款、抑制借款，维持池子流动性。
4. 清算：如果抵押物价格下跌，导致抵押率跌破安全线（比如从 150% 跌到 110%），任何人都可以调用清算函数，替借款人偿还部分债务，同时以折扣价获得等值抵押物作为奖励。这个机制保证协议本身永远不会出现坏账（只要清算及时且抵押物流动性够好）。

关键合约逻辑其实就是三件事：记账（存/借余额与利息累计）、算抵押率（依赖预言机报价）、触发清算（价格更新后检查健康度）。

期货 / 衍生品：核心是预言机 + 保证金 + 资金费率

以永续合约（Perpetual Futures）为例，链上实现和传统期货最大的不同在于没有到期日，靠"资金费率"让合约价格锚定现货价格：

1. 保证金账户：用户存入一定资产作为保证金，开仓时协议按杠杆倍数计算仓位名义价值，杠杆越高，需要的保证金比例越低，但爆仓风险也越高。
2. 预言机喂价：合约本身不知道"真实"市场价格，必须依赖预言机（如 Chainlink，或协议自建的价格聚合机制）把链下真实价格喂到链上，用来计算用户的浮动盈亏和是否触发强平。
3. 资金费率（Funding Rate）：永续合约没有交割日，如果没有约束，合约价格会和现货价格脱钩。所以协议会定期（比如每小时）比较合约价格和现货价格的差异，让多头或空头一方向另一方支付一笔"资金费"，价格偏离现货越多，费率越高，从而引导市场力量把价格拉回锚定值。
4. 强平机制：和借贷的清算类似，当浮动亏损吃掉大部分保证金、逼近维持保证金线时，系统会自动强制平仓，防止穿仓，部分协议还设有"保险基金"来兜底极端行情下的坏账。

不同协议实现方式略有差异，比如 GMX 用的是"资金池对手方"模式（交易者的盈利来自 LP 资金池），dYdX 早期用的是订单簿撮合模式，但保证金、预言机、资金费率/强平这几个核心组件是共通的。

## ④ 展望：如果扩展我们的 Swap DApp

如果要在课程的 Swap 合约基础上加功能，会按"复杂度递增、复用已有基础设施"的思路来做：

第一步，先加一个简易借贷模块。
新建一个 `LendingPool` 合约，允许用户把我们 Swap 里已经支持的代币存进去生息，同时允许超额抵押借出另一种代币。抵押率和清算价格计算需要一个价格来源——这里可以直接复用我们自己的 Swap 池子作为"内部预言机"（用池子里两种代币的比例反推价格），虽然不如接入 Chainlink 稳健（容易被闪电贷操纵价格），但作为教学 demo 足够说明原理；生产环境则一定要接外部预言机，或者做时间加权平均价，防操纵。

第二步，在借贷基础上叠加一个简单的永续合约模块。
有了借贷提供的杠杆资金池和相对可靠的价格来源之后，可以做一个最简版的永续合约：用户存入保证金开多/开空仓位，仓位盈亏 = (当前价 - 开仓价) × 仓位大小，用预言机价格结算；资金费率可以先做成简化版——固定周期内直接按多空仓位失衡程度收取一小笔费用转给劣势的一方；强平逻辑复用借贷模块里已经写好的"检查健康度 → 达标即触发清算"的函数框架，减少重复开发。

技术路径可以设计为，Swap 提供价格与流动性 → 借贷模块复用价格数据、提供资金池和杠杆来源 → 期货模块复用借贷的清算框架、再叠加保证金和资金费率逻辑。这样三个模块层层复用底层组件，也正好呼应了 DeFi 整体"金融乐高"的发展逻辑——不是每个协议都从零造轮子，而是不断在已有协议之上叠加新的金融原语。
