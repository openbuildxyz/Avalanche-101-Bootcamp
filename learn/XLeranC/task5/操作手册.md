## 1. 项目概览

### 1.1 这是什么

一个部署在 **Avalanche Fuji 测试网** 上的 **RWA（现实世界资产）Token** 演示项目。

- **业务场景**：房地产租金收益权
- **标的资产（模拟）**：上海市浦东新区"星海广场 A 座 12 层"商业办公物业未来 12 个月的租金收益权，年度租金 12,000,000 CNY
- **Token**：`XRIR`（Xinghai Plaza Rental Income Right），标准 ERC-20
- **单位映射**：**1 XRIR = 1 CNY 的租金收益权**，总上限 12,000,000 XRIR

### 1.2 实现了什么

| 功能 | 函数 | 权限 |
| --- | --- | --- |
| 发行 | `mint(to, amount)` | 仅 owner |
| 自行销毁 | `burn(amount)` | 持币人 |
| 授权额度销毁 | `burnFrom(account, amount)` | 需 allowance |
| 强制销毁 | `forceBurn(account, amount)` | 仅 owner |
| 转账 | `transfer` / `transferFrom` / `approve` | 持币人 |
| 余额查询 | `balanceOf(account)` | 任何人 |
| 总供应量查询 | `totalSupply()` / `MAX_SUPPLY()` | 任何人 |
| 资产证明更新 | `updateAssetDocument(doc)` | 仅 owner |
| 资产证明查询 | `assetDocument()` / `assetDocumentUpdatedAt()` | 任何人 |
| 紧急熔断 | `pause()` / `unpause()` | 仅 owner |
| 所有权转移 | `transferOwnership(newOwner)` | 仅 owner |

### 1.3 质量指标（均已实测）

| 指标 | 数值 |
| --- | --- |
| 测试数量 | **45 个**（含 2 个 Fuzz 测试，各 256 轮） |
| 测试结果 | `45 passed; 0 failed; 0 skipped` |
| 变异测试得分 | **11/11 = 100%**（注入 11 处缺陷全部被测试捕获） |
| 编译告警 | 0 |

### 2.2 核心文件逐个说明

#### `src/RentalIncomeRightToken.sol` —— 合约本体

整个项目的核心，166 行。继承关系：

```solidity
contract RentalIncomeRightToken is ERC20, ERC20Burnable, Ownable, Pausable
```

| 继承的合约 | 提供什么 |
| --- | --- |
| `ERC20` | 标准代币功能：转账、余额、授权、总量、`Transfer`/`Approval` 事件 |
| `ERC20Burnable` | 提供 `burn`（销毁自己的）和 `burnFrom`（按授权额度销毁） |
| `Ownable` | 提供 `onlyOwner` 权限控制、`owner()`、`transferOwnership()` |
| `Pausable` | 提供 `pause()`/`unpause()` 与 `whenNotPaused` 熔断修饰符 |

合约内自定义的内容：

| 名称 | 作用 |
| --- | --- |
| `MAX_SUPPLY` | 常量上限 `12_000_000 ether`，防超募 |
| `_assetDocument` | 私有变量，存放资产证明信息（IPFS URI / 文档摘要 / 凭证编号） |
| `assetDocumentUpdatedAt` | 资产证明最后一次更新时间戳 |
| `error EmptyAssetDocument()` | 资产证明为空时回滚 |
| `error MaxSupplyExceeded(...)` | 超过发行上限时回滚 |
| `event TokensMinted(...)` | 发行事件 |
| `event TokensBurned(...)` | 销毁事件 |
| `event AssetDocumentUpdated(...)` | 资产证明变更事件（含新旧值，可追溯） |

> **关键设计**：重写了 `_update()` 并加上 `whenNotPaused`。`_update` 是所有余额变动的唯一入口，因此**一处改动就让发行、转账、销毁在暂停时全部冻结**。

#### `test/RentalIncomeRightToken.t.sol` —— 测试套件

45 个测试，覆盖作业要求的全部 9 个场景。运行 `forge test` 即可执行。

其中 2 个是**模糊测试（Fuzz Test）**，自动生成 256 组随机输入；另有 11 个变异测试验证记录见 `README.md` 第 6.3 节。

#### `script/DeployRentalIncomeRightToken.s.sol` —— 部署脚本

含两个函数：

- `run()` —— 读取 `.env`，广播部署（真正上链用这个）
- `runWithOwner(address)` —— 不广播，供本地测试用

#### `script/TokenActions.s.sol` —— 交互脚本

部署后用来演示业务动作，5 个独立函数，**每个动作一条命令、一笔独立交易**，方便单独截图：

| 函数 | 作用 |
| --- | --- |
| `runRead(address)` | 只读查询合约全部状态（不需要私钥） |
| `runMint(address,address,uint256)` | 发行（需 owner 私钥） |
| `runTransfer(address,address,address,uint256)` | 转账（需持币人私钥） |
| `runBurn(address,address,uint256)` | 销毁（需持币人私钥） |
| `runUpdateDocument(address,string)` | 更新资产证明（需 owner 私钥） |

> 脚本内部用**无参** `vm.startBroadcast()`，签名者由命令行的 `--private-key` 决定。所以同一条命令换个私钥就能以不同身份操作。

#### `deploy-fuji.ps1` —— 一键部署脚本（Windows）

把上述所有步骤封装成一条命令：

```powershell
.\deploy-fuji.ps1              # 部署 + 演示全部业务动作
.\deploy-fuji.ps1 -UpdateDocs  # 同上，并自动回填文档里的合约地址
```

它会依次：校验 `.env` → 校验 Chain ID 必须是 43113 → 查余额（为 0 则给水龙头指引并退出）→ 编译+测试 → 部署 → 解析地址与 tx hash → 执行 mint/transfer/burn/updateAssetDocument → 打印回填摘要。

#### `foundry.toml` —— 配置

关键配置项：

```toml
solc = "0.8.24"                 # 编译器版本
evm_version = "shanghai"        # 目标 EVM 版本（兼容性最好）
optimizer = true
optimizer_runs = 200
remappings = [
    "@openzeppelin/contracts/=lib/openzeppelin-contracts/contracts/",
    "forge-std/=lib/forge-std/src/",
]
```

还包含 `[rpc_endpoints]`（Fuji RPC）与 `[etherscan]`（浏览器验证）配置。

`remappings` 的作用：让代码里的 `import "@openzeppelin/contracts/token/ERC20/ERC20.sol"` 能找到真实的 `lib/openzeppelin-contracts/contracts/token/ERC20/ERC20.sol`。

#### `.env.example` / `.env` —— 环境变量

`.env.example` 是模板（可提交）；`.env` 是你填了真实私钥的文件（**已被 `.gitignore` 忽略，绝不提交**）。

```dotenv
FUJI_RPC_URL=https://api.avax-test.network/ext/bc/C/rpc
PRIVATE_KEY=0x你的测试网私钥
SNOWTRACE_API_KEY=            # 可选，用于源码验证
```

### 2.3 依赖说明（重要）

| 依赖 | 版本 | 引入方式 | 克隆后是否需额外操作 |
| --- | --- | --- | --- |
| `forge-std` | v1.14.0 | **随仓库提交**（普通文件） | 不需要 |
| `openzeppelin-contracts` | v5.7.0 | **Git Submodule** | **需要** `git submodule update --init` |

> ⚠️ **这是新手最容易踩的坑**：因为 OpenZeppelin 是子模块，`git clone` 之后 `lib/openzeppelin-contracts/` 目录是**空的**。必须执行：
>
> ```bash
> git submodule update --init --recursive
> ```
>
> 否则编译会报 `Source "@openzeppelin/contracts/token/ERC20/ERC20.sol" not found`。

版本锁定记录在 `foundry.lock` 中（OpenZeppelin tag `v5.7.0`，commit `cab19933`）。

### 6.2 测试相关命令

| 命令 | 作用 |

### 6.3 配置 `.env`

先复制模板：

```bash
cp .env.example .env
```

（Windows：`Copy-Item .env.example .env`）

然后编辑 `.env`：

```dotenv
FUJI_RPC_URL=https://api.avax-test.network/ext/bc/C/rpc
PRIVATE_KEY=0x你的测试网私钥
SNOWTRACE_API_KEY=
```

**⚠️ 私钥安全铁律**：

1. **绝对不要**使用持有真实资产的主网私钥。请用一次性测试网钱包。
2. 生成新钱包：

   ```bash
   cast wallet new
   ```

   会输出 `Address` 和 `Private key`。地址用于领币，私钥写入 `.env`。
3. 确认 `.env` 已被 Git 忽略：

   ```bash
   git check-ignore -v .env
   ```

   预期输出 `.gitignore:12:.env	.env`（说明被忽略，不会误提交）。
4. **不要把私钥写进 README、截图或任何会被提交的文件。**

> **关于可选的 `TOKEN_OWNER` / `ASSET_DOCUMENT`**：如果不打算设置，请把对应行**整行删除或注释掉**，不要留成空值。因为部署脚本用 `vm.envOr("TOKEN_OWNER", deployer)`，空字符串会被当成"已设置"，导致地址解析失败。

1. 打开 **https://faucet.avax.network/**
2. 网络选择 **Fuji (C-Chain)**
3. 粘贴你的钱包地址
4. 完成人机验证并领取（通常给 2 AVAX，部署只需约 0.0001 AVAX）

其他可选水龙头：

| 水龙头 | 地址 | 备注 |
| --- | --- | --- |
| Avalanche 官方 | https://faucet.avax.network/ | 推荐，需过人机验证 |
| Core | https://core.app/tools/testnet-faucet/ | 需登录 Core 钱包 |
| Chainlink | https://faucets.chain.link/fuji | 需 GitHub 登录 |

领取后验证到账：

```bash
cast balance <你的地址> --rpc-url https://api.avax-test.network/ext/bc/C/rpc
```

返回大于 `0` 的数字即成功（例如 `2000000000000000000` = 2 AVAX）。

### 6.5 直接查询链上状态（`cast`）

不需要写代码，用 `cast` 就能读合约：

```bash
export TOKEN=<合约地址>
export RPC=https://api.avax-test.network/ext/bc/C/rpc

cast call $TOKEN "name()(string)"            --rpc-url $RPC
cast call $TOKEN "symbol()(string)"          --rpc-url $RPC
cast call $TOKEN "decimals()(uint8)"         --rpc-url $RPC
cast call $TOKEN "totalSupply()(uint256)"    --rpc-url $RPC
cast call $TOKEN "MAX_SUPPLY()(uint256)"     --rpc-url $RPC
cast call $TOKEN "owner()(address)"          --rpc-url $RPC
cast call $TOKEN "paused()(bool)"            --rpc-url $RPC
cast call $TOKEN "assetDocument()(string)"   --rpc-url $RPC
cast call $TOKEN "balanceOf(address)(uint256)" <某地址> --rpc-url $RPC
```

> **小技巧**：`cast` 的调用格式是 `"函数名(参数类型1,参数类型2)(返回值类型)"`。例如 `"balanceOf(address)(uint256)"`。

`MAX_SUPPLY` 应返回 `12000000000000000000000000`（即 12,000,000 × 10^18）。

## 11. 常见问题 FAQ

### Q1：`forge test` 报 `Source "@openzeppelin/contracts/..." not found`

**原因**：OpenZeppelin 是 Git 子模块，`git clone` 后目录是空的。

**解决**：

```bash
git submodule update --init --recursive
```

### Q2：`forge: command not found` / `不是内部或外部命令`

**原因**：Foundry 没装或环境变量没生效。

**解决**：重新安装并**新开终端**，或把 `%USERPROFILE%\.foundry\bin`（Windows）加入 `PATH`。

### Q3：私钥写在哪？会不会被提交？

写在 `.env`，**不会**被提交——`.gitignore` 已忽略它。随时可以验证：

```bash
git check-ignore -v .env
```

如果这条命令**没有输出**，说明 `.env` 没被忽略，**立即检查 `.gitignore`**。

### Q4：`--private-key` 明明传了，为什么还报 `PRIVATE_KEY not found`？

因为部署脚本内部用 `vm.envUint("PRIVATE_KEY")` 读取**环境变量**，而 `--private-key` 是命令行参数，两者不互通。

**解决**：

```powershell
# PowerShell
$env:PRIVATE_KEY="0x你的私钥"
forge script ...
```

```bash
# bash
export PRIVATE_KEY=0x你的私钥
forge script ...
```

（`TokenActions.s.sol` 用无参 `vm.startBroadcast()`，所以它只认 `--private-key` 命令行参数，不读环境变量。）

### Q5：为什么 `token.transfer` 之后 `totalSupply` 没变？

**这是正确的**。转账只是余额在账户间移动，不创造也不销毁代币，所以总供应量不变。只有 `mint` 增加、`burn` 减少总供应量。

### Q6：暂停之后为什么转账和销毁都失败了？

这是**有意设计**。`_update()` 是所有余额变动的唯一入口，带 `whenNotPaused`，因此暂停时发行、转账、销毁**全部**冻结（风险事件下整体停止权益流转）。

代价是暂停期间持有人也无法自行退出——这一点已在 `README.md` 第 10 节"风险边界"中说明。

### Q7：模拟部署显示的地址和最终地址不一样？

正常。模拟阶段显示的地址是本地推算结果，**最终地址由部署者的 nonce 决定**，只有真正广播后才确定。

### Q8：Snowtrace 打开了但源码是空的？

需要执行第 9 节的源码验证。未验证时浏览器只显示字节码。

### Q9：合约最大能发多少币？

`MAX_SUPPLY = 12,000,000 XRIR`，写死为 `constant`。超过会回滚 `MaxSupplyExceeded`。这是"不可超募"的强保证，代价是资产池规模变化时需要重新部署合约。

### Q10：改了合约代码后怎么重新部署？

```bash
forge build
forge test          # 确认测试仍通过
forge clean         # 清掉旧产物（可选）

# 重新部署（会得到一个全新地址）
forge script script/DeployRentalIncomeRightToken.s.sol:DeployRentalIncomeRightToken \
  --rpc-url $FUJI_RPC_URL --broadcast --private-key $PRIVATE_KEY
```

> ⚠️ **已部署的合约无法修改**。改代码 = 部署一个新合约（新地址），旧合约上的数据和余额不会迁移。因此提交前请确保合约已经定稿。

### Q11：为什么 `lib/forge-std` 不需要 `git submodule update`？

因为它是**随仓库提交的普通文件**（vendored），而 OpenZeppelin 是 Git 子模块。两者引入方式不同，详见 2.3 节。
