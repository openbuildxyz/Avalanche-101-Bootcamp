# Task 4：从一个写死的价格说起——DeFi 是怎么一层层长出来的

> 对应课程：第四章 从零部署你的首个 Avalanche DApp（讲师：Bala）

Task 2 里我在 Fuji 上部署了一个 ERC20，它带了个 `buy()`：

```solidity
uint256 public tokensPerAvax = 1000;   // 写死的价格

function buy() external payable {
    uint256 amount = msg.value * tokensPerAvax;
    _mint(msg.sender, amount);
}
```

它能跑，但它不是 DeFi，是一台**自动售货机**——价格由我一个人拍板，钉死在代码里。

这篇文档想回答的，其实是同一个问题的四种形态：**当价格不再由某个人说了算，而必须由市场产生、并且被合约信任时，会发生什么。**

## ① 定位：Swap 是 DeFi 的价格层

课程里的 Swap 用 AMM 取代了订单簿。以恒定乘积模型为例，池子里存着两种资产，储备量始终满足 `x * y = k`。

有人用 AVAX 买 LNS 时，池中 AVAX 变多、LNS 变少；为了让乘积不变，下一单的 LNS 单价必然更高。**价格不是被谁设定的，是被交易本身推动出来的。** 买得越多滑点越大——这既是成本，也是防止一次性买空池子的天然保护。

对比我那个 `tokensPerAvax = 1000`：无论谁买、买多少，价格纹丝不动。市场崩了，合约还在按 1000 卖。

所以 **AMM 的真正贡献不是"能换币"，而是让链上第一次有了持续、公开、且可被其它合约读取的价格。** 这就是 Swap 在 DeFi 里的位置：**最底层的价格与流动性层**。上面所有东西——借贷要知道抵押品值多少、期货要知道按什么价结算——都长在这个价格之上。

## ② 梳理：每一层都在解决上一层留下的问题

**阶段一 · DEX（Uniswap，2018–2020）**
解决"链上资产怎么换"。此前长尾代币没人做市，AMM 让任何人存入两种资产就能提供流动性、赚手续费。

**阶段二 · 借贷（Aave / Compound，2020 起）**
解决"持币者不卖币也能用钱"。它第一次把 DEX 的价格拿去当**风控依据**——于是价格准不准，从"交易体验问题"升级成了"协议会不会坏账的问题"。

**阶段三 · 衍生品 / 永续（dYdX、GMX，2021 起）**
解决"想做空、想加杠杆"。存保证金就能建立敞口，不必持有现货。这一层对价格的依赖到达顶点：价格错一秒，就是一次错误清算。

**阶段四 · 聚合与组合（Yearn、Curve 等）**
把前三层组装成策略。它不生产新机制，生产的是**可组合性**本身。

主线很清楚：**每上一层，对价格的信任要求就高一级，风控的分量就重一分。**

## ③ 回答：借贷和期货分别怎么实现

### 借贷 = 超额抵押 + 清算

链上没有征信，也无法追债。唯一可行的办法是让**抵押物价值始终高于债务**。

合约记录每个账户的抵押量、债务本金与累计利息，核心是一个健康度：

```
健康度 = Σ(抵押量 × 价格 × 清算阈值) / Σ(债务 × 价格)
```

- `borrow()`：借出前检查健康度 > 1，不满足直接 revert
- `liquidate()`：健康度跌破 1 时，**任何人**都能替借款人还一部分债，并折价拿走抵押物

清算奖励（通常 5–10%）是这里最巧妙的设计——它把"及时平掉坏账"外包给了套利者，协议自己不用养机器人。利率则由使用率曲线决定：池子被借空时利率飙升，逼出还款、引来存款。

### 期货 = 保证金 + 标记价格 + 资金费率

永续合约没有到期日，于是有两个问题要解决。

**一、按什么价结算？** 不能用自己盘口的成交价，否则大户砸一笔就能触发全场清算。所以引入**标记价格**，取自预言机多源报价的中位数并做时间加权。合约记录仓位名义价值与开仓价，未实现盈亏 = (标记价 − 开仓价) × 仓位。

**二、没有交割日，靠什么锚定现货？** 靠**资金费率**：多头多于空头时，多头定期付钱给空头，反之亦然。这是一个持续的经济压力，把合约价格拉回现货。

保证金分两档：初始保证金决定能开多大仓，维持保证金决定何时被强平。跌破后的清算逻辑和借贷几乎一样——第三方接手，赚罚金。

**两者的共同点**：它们本质上都不是"借钱"或"下注"的合约，而是**在价格会剧烈波动的前提下，保证协议不资不抵债的风控合约。**

## ④ 展望：给我们的 DApp 加借贷

我会先加借贷、不加期货。理由是借贷只需要**一个价格**，而期货需要**一个可信到能决定别人生死的价格**——后者对预言机的要求高一个数量级，测试网上很难做扎实。

**第一步（正好是 Task 3）：把价格接进来。**
把 `tokensPerAvax` 这个写死的常量换掉，改成从 Fuji 上的 DEX 交易对读取。做完这步，合约才第一次拥有"外部价格"这个概念。

**第二步：LendingPool。**

```
deposit(amount)           存入 LNS 或 AVAX 作抵押
borrow(amount)            借出另一种资产，借前校验健康度
repay(amount)             还款
healthFactor(user)        抵押价值 × 阈值 / 债务价值
liquidate(user, amount)   健康度 < 1 时任何人可调
```

抵押品定价复用第一步的 DEX 报价，但**必须加一层时间加权（TWAP）**。直接读交易对的瞬时储备很危险：攻击者可以用闪电贷把池价砸下去、触发清算、再把价格还原，全程在一个区块内完成。这是链上借贷最经典的攻击面，也是为什么成熟协议宁可牺牲实时性也要用 TWAP 或 Chainlink。

**第三步：和 AMM 联动。**
清算得到的抵押品，直接通过我们自己的 Swap 卖出，形成「抵押 → 借出 → 清算 → 兑换」的闭环。这步没有新机制，但它恰好演示了 DeFi 最核心的性质——**可组合性**：借贷合约不需要自己内建交易所，调用现成的就够了。

教学取舍：抵押率写死不做治理、只支持单一交易对、清算只做固定折价不做拍卖。目标是把机制跑通、把风险讲清楚，而不是做一个能上主网的协议。

---

回头看，从 `tokensPerAvax = 1000` 到 `healthFactor()`，中间隔着的不是代码量，是**对价格的态度**：前者假设价格是我说了算的常量，后者假设价格随时会变、会被操纵、会让协议破产。DeFi 这几年做的，基本上就是这一件事。
