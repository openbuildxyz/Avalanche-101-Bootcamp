# Mini-DEX AI 辅助安全自查

范围：本目录的撮合引擎、MiniExchange、资金交互 UI；不涵盖课程原始仓库，也不是独立审计报告。

## 修复案例：后段自成交导致部分订单簿变更

逐笔撮合时若一边找匹配一边减 maker 数量，再遇到用户自己的订单才抛异常，前面的有效 maker 可能已经被消耗，但整笔 taker 返回失败。这会导致账本与返回结果不一致。

例：B 先挂卖出 10，A 再挂卖出 10，A 发起买入 15。撮合先碰到 B，随后碰到 A 本人。此时必须拒绝整个请求且保持 B 的数量为 10。

最终实现先在只读候选集合中完成所有自成交与 FOK 检查，再复制并更新订单簿。回归用例 `late self-trade rejection rolls back earlier potential fills` 比较调用前后完整状态。此处描述的是实现时识别并消除的算法风险，没有声称已发生线上攻击或附有早期漏洞版本的提交历史。

## 已检查的其他约束

| 风险 | 控制与验证 |
| --- | --- |
| 未授权扣款 | 双方 EIP-712 签名，`testForgedSignatureRejected` |
| 超量重放 | 按订单 hash 记录 filled，`testFilledOrderCannotReplay` |
| 跨合约重放 | EIP-712 domain 绑定部署地址，`testCrossContractReplayRejected` |
| 自成交 | 引擎和合约同时拒绝同一交易者，地址规范化 |
| 订单撤销 / 过期 | nonce 撤销表、deadline，分别有测试 |
| 超限托管 | 两种资产分别限制总存款，`testHardCapEnforced` |
| 提款 / 重入 | 先减账户余额再转出、ReentrancyGuard、SafeERC20 |
| 转账扣费 | 入金检查实际增量等于请求量；仅支持已知标准资产 |
| 提款后旧单成交 | 再检查实时余额，余额不足回滚且 filled 不变 |
| 精度丢失 | 引擎 BigInt，BASE 整数，mUSD 6 位；拒绝 JS 小数输入 |
| 网页本地文件泄露 | 静态服务器显式路径白名单，不暴露档案或 .env |

## 尚存限制

订单本身不冻结余额，可能签多单超额承诺；最终结算会拒绝不足余额但会浪费提交者 gas。生产系统需要可验证的余额预留或过期机制。价格/时间优先由本地引擎执行，链上只执行签名限价约束，不能强制一个全局公平队列；任意提交者可以在双方接受的区间中选取成交价格。

IOC/FOK 目前是离线引擎语义，链上只逐笔结算。客户端签名登录不提供服务器认证。页面订单簿无持久化，地址记录在当前浏览器 localStorage；清理后需重新导入。代码只用于测试代币，不具备生产交易所的审计、可用性和运营条件。
