# Task 4：从 Swap 到借贷与衍生品

> 对应课程：第四章 从零部署你的首个 Avalanche DApp

## ① 定位：课程 Swap 在 DeFi 的哪一环

课程里的 Swap 属于 DeFi 最底层、也最直观的交易层：用户把一种资产放入池子，换出另一种资产。AMM 不靠订单簿撮合，而是让流动性提供者把两种资产存进池子；交易后池子的两种储备按公式重新定价。以常见常数乘积模型为例，`x * y = k`：当用户买入 Token A 时，池中 A 变少、B 变多，A 相对 B 的边际价格随之上升。手续费留在池子里，补偿 LP 承担的流动性和无常损失风险。

因此，Swap 给后续协议提供了两样基础设施：可组合的资产兑换路径，以及可观察的链上价格。课程合约若调用 Router 报价或读取 Pair 储备，本质上就是在消费这一交易层的数据；但短期储备价格容易被大额交易影响，重要业务还需要 TWAP、独立预言机和滑点保护。

## ② 梳理：DeFi 的发展进程

第一阶段是 DEX。Uniswap 将 AMM 和无需许可的流动性池普及开来，解决了长尾代币没有传统做市商、也能获得连续报价的问题。它把“交易”拆成可调用的合约接口，其他应用可以直接组合 Swap。

第二阶段是借贷市场。Aave 将闲置资产汇集成资金池：存款人获得利息，借款人存入抵押物后借出另一种资产。它解决了点对点借贷需要逐笔匹配的问题，但也把价格波动风险变成了清算机制和风险参数的问题。

第三阶段是衍生品与永续合约。以 dYdX 等永续市场为例，用户不必持有现货，也能用保证金建立多空敞口。协议通过预言机标记价格、保证金约束和资金费率，让合约价格持续向现货价格靠拢。这使 DeFi 从“兑换资产”延伸到杠杆、对冲和价格发现，同时也显著提高了预言机、清算和风险控制的重要性。

后续又出现聚合器、收益金库、稳定币和跨链等层：聚合器寻找更优成交路径，金库把策略自动化，稳定币提供记账单位，跨链让流动性跨网络流动。它们并非替代 DEX，而是建立在可交易资产、价格和结算合约之上。

## ③ 回答：借贷和期货如何实现

借贷的核心是超额抵押。合约记录每个账户的抵押数量、债务本金和累计利息，并以预言机价格计算健康度：抵押物风险折扣后的价值必须覆盖债务。用户可以存入、借出、还款和赎回；当价格变化使健康度低于清算阈值时，任何清算人都可替借款人偿还部分债务，并以折价取得抵押物。关键变量包括 LTV、清算阈值、清算奖励、利率曲线、资产上限和价格有效期。合约必须拒绝过期或异常价格，避免把闪电贷操纵的池内现价直接作为清算依据。

期货/永续合约的核心是仓位和保证金账本。用户存入保证金后，合约按标记价格记录多头或空头的名义仓位；预言机负责提供参考价格，资金费率在多空失衡时由一方支付给另一方，促使永续价格贴近现货。每次开仓、减仓和结算都要检查初始保证金；保证金低于维持保证金则允许清算。关键逻辑包括价格源的去中心化与心跳检查、仓位上限、未实现盈亏、资金费率累计值、清算罚金，以及防止同一区块价格被操纵后的错误结算。

## ④ 展望：如何扩展课程 DApp

我会先在现有 Swap 旁增加“抵押借出”模块，而不是直接上高杠杆期货。用户把课程 ERC20 或 AVAX 存入 `LendingPool`，合约从经过时间加权的 DEX 价格和外部预言机计算较保守的抵押价值，再允许借出稳定币或另一种测试代币。`PositionManager` 保存债务和利息，`LiquidationEngine` 只在健康度不足时开放清算。

前端会把 Swap 报价、滑点、健康度、清算价格和价格更新时间明确展示；钱包流程分别处理未连接、错误网络、拒签、交易处理中、链上失败与确认成功。等借贷模块在 Fuji 上经过小额测试和价格异常测试后，再增加低杠杆的永续演示：独立的 Oracle Adapter、保证金金库、资金费率结算和严格的仓位上限。这样能先验证价格与清算的风险边界，再逐步增加产品复杂度。
